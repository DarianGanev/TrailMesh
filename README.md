# TrailMesh

TrailMesh is an iPhone-first, Android-compatible outdoor application for sharing fresh trail information without depending on internet access at the moment of exchange.

Phones store signed reports and encrypted messages, carry them while people move, and exchange selected data during later encounters. The project studies opportunistic networking, store-carry-forward routing, freshness, evidence, privacy, and the practical limits imposed by mobile operating systems.

## Project specification

Read [TrailMesh.md](TrailMesh.md) for the complete product, protocol, security, testing, evaluation, and nine-month delivery plan.

The current map-first screen hierarchy, accessibility direction, and trail-session interaction are in [docs/UI_UX.md](docs/UI_UX.md). Project milestones and work tracking are maintained in GitHub.

## Current phase

M1 transport feasibility is complete. The current code contains native iPhone and Android transport probes, a frozen signed-bundle protocol fixture, and shared Python validation tools. M2 adds durable signed reports, expiry and deduplication, three-device relaying, and the first map/report interface.

M2 starts with a [signed public-report admission profile](protocol/report-v1-profile.json), a Python reference validator, and [shared valid/invalid vectors](protocol/report-v1-vectors.json). The native GRDB and Room stores will consume this contract next; the probe apps still exchange generated test bytes.

Both probe apps use **Start test session** to send and receive generated bytes automatically. Physical tests on an iPhone 17 and a Redmi Note 11 Pro 5G running Android 13 recorded 20/20 exchanges in each direction at 256 bytes, 2 KiB, and 8 KiB, with Wi-Fi and mobile data disabled and Bluetooth enabled. A separate 2 KiB test also completed 20/20 in each direction after backgrounding; the device owner reported both displays were off.

The [physical evidence](experiments/foreground_exchange/evidence-physical-v1.json) records the setup and results. The [transport notes](docs/feasibility/foreground-exchange.md) describe pairing, recovery, lifecycle behavior, and installation. These tests establish the generated-byte transport baseline; signed-report exchange, private messaging, offline maps, and multi-hop delivery are upcoming work.

The product flow is: prepare a map, start a trail session once, and let eligible reports exchange during encounters. Explore remains the home screen. Broader device and lifecycle coverage will be measured as the product grows.

## Development principles

- Work through short-lived feature branches and pull requests.
- Keep `main` releasable and use `develop` as the integration branch.
- Record platform behavior as measured evidence, not assumptions.
- Keep public reports immutable and private messages end-to-end encrypted.
- Label simulations, physical tests, and unverified claims clearly.
- Do not commit credentials, private keys, personal routes, or raw contact exports.

## Local checks and device builds

Run the reference tests from the repository root with Python 3.11 or newer:

```powershell
python -m pip install -r tools/protocol/requirements.txt
python -m unittest discover -s tools/protocol -p "test_*.py"
python -m unittest discover -s tools/transport -p "test_*.py"
```

Build and test Android with JDK 17 and the Android SDK configured:

```powershell
cd experiments/foreground_exchange/android
.\gradlew.bat testDebugUnitTest assembleDebug
```

The APK is generated at `app/build/outputs/apk/debug/app-debug.apk`. Successful platform CI runs publish the Android APK and an unsigned iPhone IPA. Follow the [device installation guide](docs/feasibility/foreground-exchange.md#build-and-install) to install the IPA using AltStore/AltServer and export test logs.
