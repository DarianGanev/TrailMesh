# Offline Rila region

The [Rila data release](https://github.com/DarianGanev/TrailMesh/releases/tag/maps-rila-osm-2026-11-16-v1) is the default in the native development diagnostics. It downloads about 64 MB and requires no account or API key. The pinned manifest SHA-256 is `862f354fa7ee81ba88c841767773607efc91f5c875c564e9faedcb196ac2c10f`.

Install the region, disable internet access, and restart the app. Reopen the region and search for `Мальовица`. Select the hut and summit as endpoints, or use the coordinates returned by the Android place search. The mapped summit approach requires maximum hiking difficulty 3 in the diagnostic controls. The default of 2 excludes that approach. The test demonstrates route calculation, not trail conditions or suitability for a hike.

From the repository root, install the pinned vector-tile validator with `python -m pip install -r tools/maps/requirements.txt` and run `python -m unittest discover -s tools/maps -p "test_*.py"` for the reference contract tests. `pack.py PACK METADATA` generates a deterministic, hashed manifest after validating local style and named places. Never use a manifest without its separately pinned SHA256.

Run `bash tools/maps/prepare_rila.sh /absolute/output` on Ubuntu 24.04 with osmium-tool 1.16.0-1build1, tilemaker 2.4.0-1build4, Docker, Python osmium 4.1.1 and Pillow 11.3.0. The reusable `map-region.yml` installs these and limits the job to 45 minutes. The build requires several GiB RAM; a 2 GiB WSL instance is insufficient. Output must be outside this checkout. The script never publishes a release.

The frozen Geofabrik Bulgaria PBF dated 2026-11-16 is SHA256 pinned. If Geofabrik is unavailable or serves bytes that fail verification, the build tries the exact bytes archived in the versioned [Bulgaria 2026-11-16 source release](https://github.com/DarianGanev/TrailMesh/releases/tag/map-source-bulgaria-2026-11-16). Both sources and the local cache must pass the same size and SHA256 checks. A complete-ways extract (22.95,41.75,24.05,42.50) feeds tiles, Valhalla 3.9.2 and places. Map extent is not a promise that every path is mapped or safe. Tiles preserve path, footway, steps and track features, names, trail difficulty/visibility attributes, huts and peaks. Wilderness huts extend the upstream OpenMapTiles mapping. Data uses ODbL; the attribution and source URL ship in the pack.

The extract explicitly sets its header bounds and tilemaker receives the same bounding box. [Osmium documents that extract headers otherwise omit bounds](https://docs.osmcode.org/osmium/latest/osmium-extract.html); [tilemaker 2.4.0 uses the supplied/header bounding box for MBTiles metadata](https://github.com/systemed/tilemaker/blob/v2.4.0/src/tilemaker.cpp). Before conversion, `validate_mbtiles.py` checks SQLite integrity, exact declared nonzero bounds, zoom and vector metadata. It checks each tile's coordinates and gzip stream, caps the compressed and decompressed sizes at 16 MiB each, and validates the MVT protobuf, layers and feature commands. `mbtiles-evidence.json` retains the archive check result.

The daylight style has muted vegetation, blue water, rust footpaths, distinct tracks, settlement/hut/peak labels and optional real DEM hillshade. It contains local resource tokens only. Noto Sans Regular includes Latin, extended Latin, Cyrillic and punctuation glyph blocks from MapLibre demotiles commit `c071b1914cb6f0ee8a8014d51a906ddfd7149848`. The punctuation block `8192-8447.pbf` contains the curly quotes and apostrophes found in Rila names and has SHA256 `f061e5b4e42e5925228534d8822b423a029569263db09f5ce44573600d45295f`. OFL and BSD licenses ship alongside the glyphs. Manifest generation requires glyph blocks for Unicode characters in the place index names and aliases. Native screenshot review covers rendered labels from the vector tiles.

Artifact `TrailMesh-Rila-region` contains `pack/` with native install paths, `release-assets/` with each file flattened to its unique GitHub-safe manifest `asset` name, `manifest.sha256`, build evidence, map metadata and `route-smoke.json`. Smoke endpoints are public OSM Malyovitsa hut and peak selected from that same PBF, retaining Bulgarian/Latin names. They are test data, not a route recommendation. The native smoke must calculate with networking disabled, validate endpoint snapping and geometry, render Cyrillic labels and restart cold. Data-build success alone does not establish these checks.

The API 37 Android job captures the native map snapshot. The hosted API 26 emulator still checks verified installation, offline search, routing and cold restart. Its x86_64 SwiftShader renderer aborted in the native snapshotter, so that job records route evidence only. Physical devices remain a separate render check.

`build-evidence.json` records source/extract hashes, tool versions and every checked-in pipeline input hash. Builds reproduce the inputs and contract; compressed map/graph byte identity across machines is not asserted. Preserve a validated pack and its exact manifest rather than silently regenerating the same revision. Publish a changed result only under a new immutable revision and catalog hash.

Publish `release-assets/rila-source.osm.pbf` with each data release under ODbL 1.0. This is the complete-ways regional extract used for tiles, routing and place names, with its SHA256 recorded in `build-evidence.json`. It stays outside the phone pack and manifest.

Run `npm ci` then `npm run validate-style` from `tools/maps` (use `npm.cmd` on Windows). The pinned official MapLibre style validator checks the complete checked-in style and the terrain style produced by `finalize_style`, including expression types. Validate a built pack with `npm run validate-style -- /absolute/path/to/pack/style.json` before publishing.
