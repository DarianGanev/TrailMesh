# Android product report storage

This is the native Android product target (`org.trailmesh.app`), separate from `probes/transport/android`. Its debug-only development panel exposes signed synthetic report creation, a consented public Nearby session, explicit clock recovery/cleanup, and redacted diagnostic export. Hiking workflows and operational maps remain deferred. Local tests do not establish physical signed-report exchange.

## Build and verify

Use JDK 17 and Android SDK 36 to compile. The supported minimum is API 26. Dependencies are pinned: AGP 9.4.1, Kotlin 2.4.21, KSP 2.3.12, Room 2.8.5, Tink Android 1.24.0, and coroutines 1.11.0. Host database tests use Robolectric 4.17 at API 28; device CI runs the same repository contract on API 26 and Android 17/API 37, plus actual Keystore and Room migration tests.

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug assembleDebugAndroidTest
.\gradlew.bat connectedDebugAndroidTest
```

The application APK is `app/build/outputs/apk/debug/app-debug.apk`; the test APK is `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`. CI publishes them under distinct `TrailMeshProduct` artifact names, verifies nonzero passing tests, and independently checks an Android-authored public test report and every valid native-encoded exchange frame with Python. Shared authoritative vectors are loaded directly from `protocol/` through source sets, rather than maintained as a second copy.

## Report encounter contract

`ExchangeSession` and `RepositoryExchangeStore` implement the transport-independent [report-exchange profile](../../protocol/exchange-v1-profile.json). They do not connect radios. A transport owner supplies a fresh random 16-byte nonce, a unique local link generation, a wall-clock callback, and monotonic elapsed times. Feed byte callbacks through `receive`, drive `tick` while idle, and call `cancel` or `disconnect` when the encounter ends. Check `isCurrent(action.generation)` immediately before dispatching each returned action. Positive acknowledgements follow a successful repository commit; `peerOutcomes` records only peer claims, not verified recipient delivery.

Inventory uses bounded verified candidate pages. Schema v4 persists a rotating inventory cursor and each report's remaining hop budget, atomically with admission. A received budget is decremented once; duplicate traffic cannot increase it. Exhausted reports remain readable but cannot be advertised or forwarded. Partial transfers are discarded on disconnect and restart from byte zero in a new encounter. Native fake links test these rules without establishing physical-radio interoperability.

An explicit emulator performance run is available with instrumentation class `org.trailmesh.app.persistence.ExchangePerformanceInstrumentedTest` and argument `mode=benchmark`. It seeds near the 25 MiB logical budget with real signed synthetic reports and measures full queries, bounded inventory pages, and concurrent ingest delay. This opt-in measurement is separate from ordinary correctness tests; report device, API, source/build and emulator limitations with its results.

The [API 26 measurement](benchmark-results/report-store-api26-v1.json) records 5,154 reports using 26,146,242 logical bytes. Full verified queries took about 12 seconds and delayed a concurrent ingest by about 12 seconds; an eight-candidate inventory page took about 26 ms. This is one emulator run, not a physical-device guarantee. Before map/session radio integration, use bounded map/history pagination or a reviewed verification snapshot strategy that preserves signed-row integrity and clock tracking. Encounter timeouts must remain active during queued storage work.

## Repository contract

`ReportRepository.open(context, databaseName)` opens Room and applies non-destructive migrations off the UI thread. `author` creates an immutable signed report and commits the bundle, report projection, relay/outbox state, and replay marker atomically. `ingest` verifies strict UTF-8/JSON, canonical bytes, content ID, Ed25519 signature and freshness before a short transaction rechecks expiry, duplicates, budgets and the clock. `Stored` is returned only after commit; signature authenticity does not establish that an observation is true.

Use `reports(now, bounds, includeExpired)` for immutable map projections, including bounds crossing the antimeridian. History requires `includeExpired=true`. `forwardable(now)` returns a copy of the original accepted wire, without changing signed timestamps or resigning. Stored signatures, bytes, SQL types, and projection fields are checked before display, forwarding, duplicate confirmation, or cleanup. Lost payloads with a live seen marker produce an explicit error rather than a false duplicate acknowledgement. Storage, signing and clock failures propagate; exchange code must not map them to success.

The initial shared policy is 25 MiB of logical signed-data bytes, with remote admissions limited to 20 MiB, reserving 5 MiB for local authoring. SQLite pages, indexes and WAL overhead are additional. Remote authors may contribute at most 20 newly accepted reports per rolling local hour; duplicates and failed transactions consume no allowance. Seen IDs remain until signed expiry plus 24 hours and are capped at 10,000. Admission rejects quota rather than evicting reports or replay markers under an unverified clock. Forwarding ends at the earlier of signed expiry and admission plus 72 hours; zero-hop reports are retained but not forwarded.

A backward clock returns an explicit clock failure. Only after user confirmation, `recoverClockAfterUserConfirmation` quarantines existing reports as identifiable expired history and resumes at the corrected time. Quarantined reports cannot become current or forwardable. Remote entries conservatively retain their author allowance for one hour after each recovery. Only `reclaimExpiredReportsAfterUserConfirmation`, after confirmation of clock accuracy and deletion, removes expired history and elapsed seen markers; recent remote rate windows are preserved. This intentionally replaces automatic seven-day deletion. The product UI still needs to expose these actions.

Database work and signing run off the main thread. Cancellation before an operation enters its protected transaction prevents mutation. Once the transaction begins, it finishes and returns its committed outcome, allowing the caller to make an honest acknowledgement decision. A SQLite failure closes and reopens that repository's connection pool before permitting reuse, because a failed commit can leave Android's connection state uncertain. It still reports the failure; it never infers success from recovery. A caller may lose a response or terminate after commit; retrying a valid retained report is safe.

## Local selection and bounded report pages

`reportPage(now, bounds, includeExpired, after, limit)` reads at most 64 raw reports plus one candidate lookahead. It verifies original signed bytes and stored projections before filtering bounds, expiry or quarantine. Pages keep observation time descending and ID ascending; continue using `nextCursor` while `hasMore`, including empty filtered pages. `inspectedCount` counts verified raw rows. Queries use the v5 observation/ID index with two range seeks (equal observation with later IDs, then older observations), so late cursors do not rescan the preceding index prefix. Existing `reports` and `forwardable` APIs retain their full-query behavior for compatibility.

`RelevancePolicy` uses the shared [local relevance profile](../../protocol/relevance-v1-profile.json) and [literal vectors](../../protocol/relevance-v1-vectors.json). A configured manual area works without GPS; an optional route corridor and usable GPS area form a union. Routes are immutable local snapshots, use shortest spherical arcs across poles and the antimeridian, and never enter exchange frames. Missing or unusable configuration returns `configurationRequired`; invalid configuration returns `invalidConfiguration`. Signed report accuracy does not widen relevance. The strict `evaluateLocal` settings boundary accepts deserialized maps/lists and preserves integer types; a caller's JSON decoder remains responsible for rejecting duplicate keys before producing a map.

`SelectedRepositoryExchangeStore(repository, context)` freezes one immutable context per encounter. The encounter owner must cancel when its configuration changes. It filters each bounded eight-candidate inventory page while retaining raw ID cursor/order and rechecks relevance on load. Signature, clock, quarantine, expiry, hop, quotas and durable ACK decisions remain authoritative in the repository. This adapter does not start radios or establish physical delivery.

Schema v5 adds only the observation/ID index; migrations preserve v1?v4 signed payloads and relay state. Shared host/device tests cover relevance decisions, ordering, empty filtered continuations, corruption beyond the first verification budget, quarantined history, clock changes and indexed pagination. The [API 26 bounded-page measurement](benchmark-results/report-store-api26-v2.json) records a 64-row verified report page at about 270 ms, a late equal-observation cursor at about 268 ms, and concurrent ingest at about 283 ms during a bounded report page (compared with about 18.3 seconds during a retained full-history query). These are single-run emulator observations, with APK hashes and normalized source provenance, not physical radio or timing guarantees.

## Signing identity

`ProtectedSigningIdentityStore.createNew()` is an explicit one-time action. `loadExisting()` never creates a replacement identity. A 32-byte Ed25519 seed is encrypted with AES-256-GCM using a non-exportable Android Keystore wrapping key, authenticated with a versioned domain, and stored atomically under app-private `noBackupFilesDir`. Creation flushes both file contents and the directory entry before returning. A file lock serializes creation across instances and processes. No seed is stored in SQLite. Legacy backup, cloud backup and Android device transfer are explicitly excluded for this development product.

The wrapped-seed fallback is **not** a non-exportable Ed25519 Keystore key or a promise of hardware backing. Signing unwraps the seed into process memory and checks identity continuity. Missing/invalidated keys, corrupt ciphertext and failed persistence fail explicitly without replacing the identity. A failed first save can leave an orphan wrapping key; creation then fails safely and requires a future explicit reset flow, rather than silently selecting a new identity.

## Schema and evidence

Committed Room exports cover deliberate pre-release v1, additive v2 (persisted clock), and v3 (quarantine). They do not represent previously shipped Android databases. Tests seed real signed bytes in older on-disk schemas, migrate and compare signed blobs, projections, relay/replay state and indexes, and verify migration rollback/retry and refusal of unknown newer schemas. Runtime constraint triggers supplement Room's exported schema for binary widths, signed time ordering, origin flags, relay caps and the singleton clock.

Regression tests cover malformed/valid vectors, real signing, reopen and concurrent duplicate admission, immutable original wire, transaction rollback, SQLite exhaustion, capacity reserve, author rate limits, bounded seen IDs, expiry boundaries, explicit history, corrupted stored data, backward/future clocks, quarantine, confirmed cleanup, cancellation, migrations and actual Android Keystore behavior. A separate device test stores a report, force-stops the application, and verifies the same bytes and duplicate result in a new process. These are local/emulator results, not physical radio or lifecycle evidence.

## Public report session development controls

Debug builds provide explicit public-sharing consent, Start/Stop/Resume, signed synthetic test reports, a bounded saved-test-report list, and a user-initiated JSON export. The fixed synthetic Sofia area has center `(426977000, 233219000)` and radius 5,000 m. Creating a report is a separate action: Start never creates a public report. New synthetic reports use the shared `SYNTHETIC TrailMesh test ` note prefix, category/status `trail/muddy`, one-hour expiry and three hops. Protected identity creation occurs only for a genuinely missing first-launch identity; corrupt or unavailable identities are never replaced.

`ReportSessionCoordinator` runs one existing exchange engine per link. It admits four connecting/active/draining links, 32 FIFO candidates and 32 retired endpoint IDs per SDK epoch. Aggregate admission reserves at most 64 receive callbacks and 256 KiB before copying bytes or creating coroutines. Each link serializes receive and dispatch while independent 250 ms monotonic ticks and immediate Stop remain available during repository waits. Captured epoch/generation tokens prevent old callbacks from affecting replacements. Normal actions become stale when the engine closes; tagged terminal actions and bounded SDK send completions drain for at most two seconds. Per-peer cooldowns use a bounded 64-entry LRU and there is no eight-peer session lifetime cap.

The product adapter pins Nearby 19.5.1 with `P2P_CLUSTER`, distinct service `org.trailmesh.reports.v1`, and exact temporary advertisement `TMR1|<32 lowercase nonzero hexadecimal characters>`. Lower advertisement ID initiates; each exchange HELLO uses a separate fresh secure nonce. Advertising contains no author identity, route, location or interests. Nearby participants remain unverified: consent explains public visibility, and signatures protect report integrity without authenticating a person or link peer. No SDK send completion is treated as durable storage or final delivery.

Android uses a user-started `connectedDevice` foreground service with a Stop notification and `START_NOT_STICKY`. Missing grants, radio failure and repository clock/storage errors pause visibly. Process death requires explicit Resume. The SDK's location compatibility failures request the precise additional grant on Resume. These implementation choices do not establish vendor-specific screen-off behavior; actual phones and lifecycle measurements remain required.

Production selected-store reads sample the supplied wall-clock closure inside each protected transaction. Selected inventory and rotating cursor advancement commit together, avoiding false backward-clock errors when another peer commits between sampling and queue admission. Existing fixed-time APIs keep their strict semantics, and actual backward corrections are never clamped away.

Exports follow `trailmesh.report-session-log` version 1, with at most 512 fixed-code events and 64 saved synthetic records. A bounded repository read freshly verifies signed stored bytes and derives canonical-core/original-wire SHA-256 hashes, observation times, expiry/quarantine flags and remaining hops. No raw wire, signing secret, report note, coordinates, route or SDK authentication code is exported. Source commit is optional; record the matching APK source/artifact when collecting physical evidence. Matching hashes corroborate stored immutable reports; range, process restart and concurrent physical radios require operator observations.

Shared JVM/device repository tests exercise four simultaneous fake-radio peers with real signed Room records, bidirectional transfer, cross-peer duplicates, stalled-peer isolation/refill, and Stop after a real commit. Core tests additionally cover admission, callback/byte overflow, context changes, send failures, terminal drain, reused endpoints and more than eight historical peers. These are fake-radio/emulator checks, not physical-radio evidence.
